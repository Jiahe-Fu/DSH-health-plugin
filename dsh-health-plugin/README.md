# dsh-health-plugin — DSH 私人健康助手插件

把 DeepSeek Harness 变成一个**睡眠优先**的私人健康助手：一个和「标准模式 / PTC 模式 / 极简模式 / 创造模式」并列的**健康模式**、一套 `health_*` / `sleep_*` 工具、一个本机明文健康档案，和 Web 里的**健康面板**。

设计上有意借鉴了 [ChatGPT 的 Health 功能](https://openai.com/zh-Hans-CN/index/health-in-chatgpt/)——纵向趋势对比、数据与日常对话打通、无数据时也能用——但**反过来做数据主权**：数据全在本机明文文件里，插件自身不发任何网络请求。

---

## 一句话定位

普通 AI 助手对失眠只会说「少喝咖啡、早点睡」，这是**已经被证明基本无效**的建议。这个插件给的是**可执行到分钟级的 CBT-I（失眠认知行为治疗）方案**，并且在给出方案之前先做禁忌与红线筛查。

## 组成

| 部分 | 内容 |
|---|---|
| **健康模式**（agent preset `health`） | 私人健康顾问人设 + 全部健康工具 + 文件/Shell/Web 工具 + `time-context`（把「昨晚」解析成日期）+ `schedule`（就寝与用药提醒） |

| **HTTP 路由** | `/api/health/*`，面板的数据来源 |
| **健康面板** | 设置页「健康」：睡眠首屏、趋势图、记录管理、档案编辑、数据与隐私 |
| **数据层** | `~/.dsh/health/` 下的纯文本 JSON / JSONL |

## 数据存放（全部明文，你可以随时打开、备份、删除）

```
~/.dsh/health/
├─ profile.json          档案：出生年、身高、疾病史、长期用药、目标起床时间、职业
├─ records/2026.jsonl    记录流水，一行一条 JSON，追加写入
├─ plugin.log            插件自证日志：每次 apply 逐步记录注册结果
└─ README.txt            运行时自动生成的说明
```

- 写入是**原子**的（临时文件 + rename），崩溃不会留下半行。
- 原子写在 Windows 上**带重试**：rename 覆盖一个被瞬时占用的文件会返回 `EPERM`/`EACCES` 而不是永久失败，不重试的话"删除一条记录"会偶发地直接报错。延迟短且有界，真正不可写的路径依然会抛出原始错误。
- 单行损坏会被**跳过并报告**，不会连带丢掉整年历史。
- 删除整个目录即可清空；插件下次使用会重建空档案。
- 路径可在插件配置 `dir` 里改。

### `plugin.log` 是干什么的

它记录插件每次启动时每一步注册的结果，例如：

```
2026-10-09T12:21:06.321Z tools   OK 9 registered
2026-10-09T12:21:06.321Z prompt  FAILED cannot get property "systemPrompt" without inject
2026-10-09T12:21:06.322Z skill   OK health-insomnia-protocol
2026-10-09T12:21:06.323Z routes  OK 15 registered
2026-10-09T12:21:06.323Z effect  OK disposer captured
```

留着它有三个具体理由，都是实际踩过的坑：

1. **宿主会吞掉激活诊断**，而且第三方插件行的 `status` 字段对「已挂载并正常工作」与「压根没挂载」显示得一模一样。没有这份日志时只能靠猜。
2. **只有 `apply` 跑起来才会创建这个目录**，所以文件在不在本身就是一次激活判定。
3. DSH 的上下文对**未在 `inject` 里声明的服务**会拒绝属性访问（`cannot get property X without inject`）。本条正是靠日志抓到的：`systemPrompt` 没声明时提示词段落被静默丢弃，而其余注册全部成功。

## 数据来源（每条记录都标来源）

健康档案最危险的一种损坏方式，是**把编造的数字放在用户实测数字的位置上**——面板事后分不出两者，而所有平均值、睡眠效率、趋势都会因此悄悄失真。所以：

- 每条记录都带 `source` 字段，取值受限于 `user` / `agent` / `import` / `device` / `sample`
- `sample` 或 `synthetic` 的记录在面板上**强制标注「示例数据」**，并提供「清除全部示例数据」一键操作
- 用户自己在面板表单里填的记录标 `user`；代理按用户口述记的标 `agent`（两者都正常显示，不加警示角标）
- 系统提示词里写死了边界：**只记录用户自己报告或实测的数字**，不许为了演示、测试或"让界面好看"而写入，也不许根据印象或常识推测数值。没被告知的数值就不存在——缺失是允许的状态，编造不是

这条不是假想的洁癖。本插件第一次跑通时，我为了验收数据通路，用 HTTP 路由写入了一条合成的睡眠记录（卧床 7.7h / 睡眠 6.9h / 效率 90%）。用户在面板上看到它时，第一反应是"你怎么意淫出我的睡眠时长的？"——**这个反应完全正确**：那条数据是我造的，而面板当时没有任何方式说明这一点。来源标记与示例数据一键清除就是为此加的。

## 健康模式开关（`/health`）

在对话里输入：

| 命令 | 作用 |
|---|---|
| `/health` | 在开与关之间切换 |
| `/health on` | 开启（可重复执行） |
| `/health off` | 关闭 |
| `/health status` | 只看当前状态，不改变 |
| `/health <一句话>` | 开启模式，并把这句原话交给助手 |

最后一行是有意设计的：以 `/` 开头的输入会被**整行**当作命令消费，所以如果 `/health` 拒绝后面的文字，用户说的话**根本到不了模型**。第一版就是这样把一句完整的睡眠描述吞掉的。现在的规则是——**只有被识别的单个词才算子命令**，其余一律视为用户原话；`/health on <文字>` 同理，`on` 后面全部算消息。

把这句话送进模型用的是 `agent.inject(createUserMessage({ content, source }))`——消息对象**由 DSH 自己的 `createUserMessage` 构造**（从安装目录解析 `@deepseek-ai/dsh-llm`），不是手搓一个形状相似的 JSON。若该 helper 不可用，命令会明确提示"请把这句话作为普通消息再发一次"，并把结果写进 `plugin.log` 的 `inject-helper` 行，而不是静默丢弃。

开关是**按会话**的，存在 Host 进程内存里，**不写进会话日志**——所以它不会悄悄影响你没打开过的会话，重启后回到关闭状态（默认）。

实现上，命令在**不触发模型回合**的情况下翻转一个标志，提示词里那行模式说明是一个 `{{health_mode}}` 变量，在每次组装时求值。这样做的两个好处：一次 `/health` 立即影响**下一条**消息；而提示词前缀保持稳定，可以继续命中缓存（不需要为两种模式各存一份 system prompt）。

关闭时仍然可以记录与查询数据（你直接说数据它就记），但不会主动展开健康建议。

## 用药管理

登记的是**处方本身**——药名、单片剂量、每次几粒、频次、具体钟点、是否需要随餐。插件**绝不替你决定剂量**：它只记录医生说的并据此提醒。

```
~/.dsh/health/medications.json   长期用药（一份 JSON，可读可改）
records/<年>.jsonl               每次服药/漏服作为 medication 记录追加
```

- `medication_regimen`：登记 / 查看 / 删除长期用药
- `drug_notes`：取**成文**的忌口、相互作用、监测项目、支持护理与就医红线
- `medication_taken`：记录某一次实际服药（或故意跳过）以及不良反应

**一条硬规则**：`frequency` 是「每日两次」却**没有给时间**时会被**拒绝**——没有时间就发不出提醒，静默接受会造出一条永远不响的用药计划。

### 关于异维A酸（本插件已内置成文说明）

内置条目 `isotretinoin` 收录了说明书级别的事实，其中和日常最相关的几条：

- **必须随餐服用，且餐中要有脂肪**——空腹吃吸收明显下降，等于白吃
- 软胶囊/胶囊**整粒吞服**，不要咬破
- **不喝酒**：加重血脂升高与肝酶异常
- **不额外补维生素A**（含维A的复合维生素也不行）：叠加中毒风险
- 妊娠期**绝对禁用**（明确致畸）；服药期间及停药后至少 1 个月**不得献血**
- 避免与**四环素类**同服（颅内压升高风险）；避免磨皮/激光等皮肤操作
- 常规复查：**血脂（尤其甘油三酯）、肝功能**；育龄女性按医嘱做妊娠试验
- 支持护理：**规律补水**、随身润唇膏、温和保湿、无防腐剂人工泪液、必要时加湿器
- 需要就医的红线：视力改变或持续头痛、剧烈腹痛（警惕胰腺炎）、情绪显著低落或有自伤念头（12356 / 120）、黄疸、大面积水疱或发热伴皮疹、呼吸困难

**剂量与疗程以你的处方为准**：本插件不知道医生让你一次吃几粒，所以它不会替你算，只会在你登记后按你给的时间提醒。

### 没有成文条目时：自动联网查，带引用返回

成文条目只能覆盖人工整理进去的几个药，而药物知识是无限的。所以 `drug_notes` 有**两条来源，按顺序**：

1. **先查本插件的成文条目**（人工整理、可审阅）
2. **没有条目时自动联网检索**——也可用 `source: "web"` 强制联网、`source: "notes"` 禁止联网；`focus` 可只查一个面（`timing` / `restrictions` / `monitoring` / `sideEffects` / `supportive` / `redFlags` / `dosing`）

联网路径的硬约束：

- 检索锚定**药品监管与权威医学数据库**（DailyMed、MedlinePlus、PubMed/PMC、FDA、EMA、MSD、NMPA 等），并按**权威等级**排序：等级永远优先于语言与格式，一个博客在任何语言下都不该压过监管机构的页面
- **语言与区域偏好**：药名是中文时（如「褪黑素」）用中文查询词检索、优先中文来源（默沙东诊疗手册、药典在线、丁香园用药助手等）。原因是实测踩过一次：检索命中了 EMA 的匈牙利语与捷克语附件，技术上"查到了"，实际上对中文读者毫无用处
- **可读页面优先于 PDF**：同样是监管机构的内容，HTML 能被抽取、PDF 常常只拿到二进制壳子，所以 PDF 排在同等权威的 HTML 之后（但不排除——监管机构自己的说明书正是最该看的）
- **只引用有权威归属的来源**：未知域名的结果直接丢弃。宁可说"没查到"，也不把一个博客当成药品参考递给你
- 分句阈值**按文字体系区分**（中文 12 字符、拉丁 40 字符）。最初统一用 40，导致中文页面几乎全被丢弃——这种 bug 以"什么都找不到"的方式失败，最难发现
- 读取配额限制的是**尝试次数**而不是成功页数：否则第一个页面只要没命中关键词就会把配额吃光，后面全部读不到
- 返回的是**原文摘录 + 来源链接**，不是模型的转述。每段都带 URL，你可以自己点开核对
- **提取不到摘录时不是死路**：会把检索到的页面链接一并给你，并说明常见原因是外文或 PDF
- 每条都带边界声明：这是网页摘录、可能不含最新信息、**以说明书为准**
- 检索失败会**如实报告失败原因**，不假装查到了
- 当前配置没有联网服务时，明确说"无法替你查网"，退回说明书/药师
- **剂量永远不由它给出**：剂量属于处方与说明书

成文条目里的每一条都带 `sources` 字段（来源名称 + 链接），面板底部会列出「本条目依据」，可逐条核对。目前收录：**异维A酸**、**多西环素**、**褪黑素**。

> 这条改动的由来：我最初让 `known=false` 时直接回退到"插件没有说明，请问药师"。用户指出这不对——**插件应该去查，而不是把人打回来**。于是加了联网路径，同时守住"引用而非转述"的底线。

## 隐私边界（请认真读这一段）

1. **落盘是纯文本、不加密**。任何能读你用户目录的程序都能读到。
2. **本地存储 ≠ 隐私**。当你在对话里讨论这些数据时，内容会作为提示词**发送给模型提供商**。想避免，就「只记录、不提问」，或只描述不引用具体数值。
3. **健康数据本身不会联网**，但**药物查询会**：`drug_notes` 查不到成文条目时，会把**药名**（不含你的任何健康记录）发往搜索引擎并读取相关页面。这是目前唯一的出站请求。你可以用 `source: "notes"` 关掉它，方法是在对话里说明"只查本地说明"，或让面板的用药页签不展开说明。除此之外没有任何遥测或云同步。

## 睡眠优先：插件真正在做什么

慢性失眠的一线治疗是 **CBT-I**，不是安眠药，也**不是睡眠卫生教育**。CBT-I 的活性成分是**睡眠限制**与**刺激控制**。本插件据此实现：

**先算，再建议。** 所有派生指标由代码计算，不让模型心算：
卧床时间 TIB、总睡眠时间 TST、**睡眠效率 SE = TST / TIB**、入睡潜伏期 SOL、夜间觉醒 WASO、睡眠中点（昼夜节律相位）、睡眠负债。

**锚点是固定起床时间，不是就寝时间。** 这与直觉相反，但固定就寝时间会把失眠者按在床上清醒更久。

**按周按 SE 调整卧床窗口**（每次最多 30 分钟，硬下限 5 小时）：

| 近 14 晚平均 SE | 动作 |
|---|---|
| ≥ 90% | 卧床时间 +15~30 分钟 |
| 85%–90% | 维持不变 |
| < 85% | 卧床时间 −30 分钟（不低于 5 小时） |

**先筛查，再开方。** `sleep_analyze` 返回的 `safety.refusals` 非空时，行为方案会被**故意扣留**：

- **红线症状**（疑似呼吸暂停/憋醒、不宁腿、猝倒、自伤或自杀风险、精神症状）→ 立即就医，不做行为干预
- **禁忌**（双相情感障碍、癫痫、妊娠、驾驶/机械操作等需高度警觉职业）→ 睡眠限制疗法不适用，请医生评估
- **数据不足**（< 3 晚不调整窗口；< 7 晚只给固定起床时间与记录要求）

**相关性只作提示，不作结论。** 咖啡因/酒精/关屏时间与入睡耗时的相关系数会展示，同时显示样本量 `n`，并明确写出「这是相关，不是因果」。

## 医学安全边界（写进人设与代码）

- 明确声明**非医疗器械、不提供诊断、不替代面诊**。
- 遇到红旗症状 → 中止建议流程，输出**急救指引**（中国大陆 120；心理危机 12356 / 120）。
- **不调整处方药剂量**；药物相互作用只提示「请咨询医师或药师」。
- 临床危险读数（血压 ≥180/120、体温 ≥39 °C、血糖 ≥13.9 或 <3.9 mmol/L、静息心率 >100 或 <50）会被代码标记并回传给模型。
- 缺失数据不许推测；涉及数据时标注日期与来源。

## 安装

首选用 DSH 自己的通道（需要审批开启）：

```
plugin_manager(action: "install_bundle", target: "<本插件绝对路径>")
```

审批关闭时，用仓库里的等价脚本（做的事与 `install_bundle` 相同，每一步都校验并留 `.bak` 备份）：

```powershell
# 在 Harness 自带的 Node 里跑，才能解析安装目录内的 asar 模块
$env:ELECTRON_RUN_AS_NODE="1"
& "C:\Users\<你>\AppData\Local\Programs\DeepSeek Harness\DeepSeek Harness.exe" `
  "dsh-health-plugin\tools\install-profile.mjs"
```

卸载：`... install-profile.mjs --uninstall`。预演：`--dry-run`。

> **新增 preset 需要重启 DSH**：替换已加载的包不走 HMR。装完请重启，然后在设置 →「Agent 预设」的**自定义**分组里选择「健康模式」。

## 从 npm 安装（发布之后）

```powershell
& "<Harness 安装目录>\DeepSeek Harness.exe" `
  "dsh-health-plugin/tools/install-profile.mjs" --from-npm dsh-health-plugin
```

包名是 **`dsh-health-plugin`**。不能叫 `dsh-health`：那个名字在 npm 上已被**另一位 DSH 插件作者**占用（`dushaobindoudou`，描述为 "Live health status for dsh installs — name reserved"）。那是正当占用，所以本包改名，而不是去要这个名字。

> 改名的连带影响：preset 行 id 也从 `dsh-health` 变成 `dsh-health-plugin`。**若你装过旧版本，必须先 `--uninstall` 再装**，否则两个 bundle 都会声明 `preset-health` 而冲突。
> 数据目录与 URL 前缀**故意保持不变**（仍是 `~/.dsh/health/` 与 `/dsh-health`）——跟着改名会让你已有的健康记录失联。

## 发布前检查（维护者）

```powershell
# 打包并列出实际会发出去的文件
& "<Node>" "<pnpm.cjs>" pack --pack-destination "$env:TEMP\dsh-health-pack"
tar -tzf "$env:TEMP\dsh-health-pack\dsh-health-plugin-0.1.0.tgz"

# 把打好的包当消费者解包并加载，验证"发布出去的东西能用"
$env:ELECTRON_RUN_AS_NODE="1"
& "<Harness>.exe" "tools/verify-tarball.mjs" "$env:TEMP\dsh-health-pack\dsh-health-plugin-0.1.0.tgz"

# 预演发布（不校验登录）
& "<Node>" "<pnpm.cjs>" publish --dry-run --access public
```

`verify-tarball.mjs` 不只是列文件：它把 tarball 解开、**从解开的副本里 import**，并逐个检查相对导入是否都在包内、client 半侧是否以包名注册、bundle patch 是否指向本包。文件清单只能证明发了什么，证明不了能用——而**已发布的包发现缺文件，只能靠发新版本补救**。

```powershell
# 重启前闸门（见下）

# 单独校验 preset 每个孩子行的 config：一个不存在的字段会让 preset 激活失败，

& "<Install>\DeepSeek Harness.exe" "dsh-health-plugin\tools\validate-preset.mjs"
```

### 关于这扇闸门

`preflight.mjs` 会在重启前检查四类只会在重启后才暴露的问题：

1. **preset 的每个孩子行都能解析**——写错一个包名会让**整个 DSH 启动失败**；
2. **每个孩子行的 config 都被它自己的 schema 接受**——这一项抓到过真缺陷：`tool-fs-search` 要求 `sampleOverCapGlobResults`、`tool-todo` 要求 `allowParallelInProgress`，缺了它们 preset 会**激活失败**，而你只有在选中「健康模式」时才会看到它坏掉；
3. **`createUserMessage` 能解析**——`/health <文字>` 把句子交给模型的唯一途径；不可用时命令会降级为"请重发"；
4. **活体 profile patch 与 bundle patch 一致**——保证磁盘上装的就是这一个版本。

`tools/` 下的 `grep-asar.mjs` / `slice-asar.mjs` 是开发期用来读 app.asar 内官方插件源码的探针，不参与运行。

## 已知限制

- 不做蓝牙/手环/Apple Health 数据接入；没有标准本地接口，属另一个项目。
- 不加密、不云同步、不多设备。
- 面板写操作只覆盖「记录昨晚」；其他记录请通过对话或 `health_record` 工具写入。
- `schedule` 与 `time-context` 来自 DSH 的实验性 bundle，若某个 DSH 版本移除了它们，健康模式会在 roster 里显示为加载失败（不会影响其他模式）。
- 失眠报告是行为记录与筛查，**不是诊断**。
